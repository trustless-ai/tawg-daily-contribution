# Staged rollout

Promotion is explicit and sequential. A later gate never waives an earlier one.

1. **Bootstrap:** preview and import the Telegram Desktop JSON without media. Confirm only sanitized Telegram records are written and the raw export remains outside the repository.
2. **Source and knowledge acceptance:** audit `knowledge/meta/sources.yml`, then fetch GitHub, canonical ERC/EIP, and Ethereum Magicians evidence transiently. Review aliases, metadata-only source/claim ledgers, ERC pages, links, citations, gaps, and privacy lint. Confirm `data/github/` and `data/magicians/` do not exist.
3. **Observe-only L1:** manually dispatch `main` with input `runtime_mode=observe`; verify all ordinary group messages persist and only mentions create reply jobs.
4. **Daily dry run:** at or after a `23:00 UTC` cutoff, print and review at least one Daily for exactly `[previous 23:00 UTC, current 23:00 UTC)`. The command collects live external activity immediately before generation and neither writes an artifact nor delivers Telegram messages.
5. **Live Daily:** set `TAWG_DELIVERY_ENABLED=true` only after the target chat and exact UTC window are confirmed.
6. **Read-only mentions:** enable replies while correction transactions remain operationally unapproved.
7. **Corrections:** permit cited current-knowledge and TAWG-local alias transactions after reviewing the refusal and ambiguity behavior.
8. **Modal deterministic gate:** run the webhook normalizer, Modal adapter, and webhook ingestion tests with fake identifiers and fake services. No paid model, Telegram call, Modal call, or GitHub write is allowed.
9. **Modal shadow:** deploy the reviewed adapter without registering a Telegram webhook. Keep `TAWG_RUNTIME_MODE=poll`, `TAWG_MODAL_MAINTENANCE_ENABLED` exactly `false`, and the existing GitHub polling schedule active. Inspect safe deployment metadata only. The no-paid, no-real-identifier synthetic dispatch remains in the local fake tests; the current production ingestion entrypoint can process unrelated actionable replies, so a deployed synthetic request is not a deterministic no-paid test.
10. **Webhook cutover:** follow [`modal.md`](modal.md#webhook-cutover) without abbreviating its order. In a controlled idle window, manually call `setWebhook` with the exact secret token, `allowed_updates=["message", "edited_message"]`, and `drop_pending_updates=false`, then verify `getWebhookInfo`. Set `TAWG_RUNTIME_MODE=webhook`, disable the scheduled Actions workflow, and confirm no Actions run remains active. Only after Actions is disabled and idle, set `TAWG_MODAL_MAINTENANCE_ENABLED` to exact lowercase `true` and redeploy the exact reviewed commit currently on `main`. Then exercise the deployed endpoint with one real ordinary message and one real mention, proving one repository record and one correctly threaded `delivered` reply. Keep Actions disabled after acceptance; retain its workflow definition for rollback.

At every phase, Telegram has exactly one consumer. A configured webhook makes `getUpdates`
unavailable. GitHub webhook mode is a fallback guard, not permission to run Actions maintenance
beside Modal: the scheduled Actions workflow is disabled before real acceptance because both paths
process replies. Deployment never changes Telegram webhook state automatically.

Rollback is non-destructive. For the pre-webhook stages, unset `TAWG_DELIVERY_ENABLED`, disable the workflow, or return to `TAWG_RUNTIME_MODE=observe`. After webhook cutover, follow [`modal.md`](modal.md#rollback-without-dropping-updates): set `TAWG_MODAL_MAINTENANCE_ENABLED` to exact `false` and redeploy the exact reviewed `main`. A pre-delete drain is useful but cannot replace the mandatory post-delete drain. Then call `deleteWebhook` with `drop_pending_updates=false` and verify `getWebhookInfo.result.url` is empty. After the URL is empty, require that all retries are exhausted and zero active, queued, or retrying `repository_worker` calls remain. Only then may you restore `TAWG_RUNTIME_MODE=poll` and enable the single GitHub polling schedule. Reconcile pending work from the repository. Do not delete sanitized Telegram history, receipts, metadata, cursors, delivery attempts, or Git history. An `ambiguous` delivery remains operator-reviewed; rollback is not permission to resend it.

Local knowledge compilation may use the developer's local Codex identity. The Actions runner uses the operator-configured DeepSeek endpoint through the pinned Claude Code CLI; Claude sessions are not durable, so repository state is the only long-term context. Validate the workflow manually on `main` with input `runtime_mode=observe` before enabling delivery.
