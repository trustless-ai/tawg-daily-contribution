# ERC-8263: Onchain Proof Layer for AI Agents

## Summary

The agent-ercs implementation draft defines a minimal on-chain commitment layer that anchors a proof hash together with an agent identity scheme and identifier.

## Status

Implementation and test evidence were verified in the Trustless AI org. No canonical normative ERC source is registered, so this page does not claim published-standard status.

## Motivation

A small, uniform event surface lets independent verifiers recompute an artifact commitment and match it to chain history without trusting the issuing service.

## Architecture

An action artifact is reduced to a non-zero commitment, then emitted with identity binding data. Verification and profile interpretation remain off-chain.

## Interfaces

The implementation exposes an on-chain proof interface with basic and auxiliary anchoring entry points and a canonical proof event.

## State machine

This is an append-only anchoring flow rather than a multi-stage lifecycle: validate canonical inputs, emit the anchor event, then let external verifiers resolve and recompute it.

## Implementation

The org source enforces non-zero proof hashes and canonical combinations of anonymous, registry, and URI-hash identity schemes.

## Security considerations

An anchor proves that bytes were committed at a point in chain history; it does not prove that an identity is correct, a payload is valid, or an action was authorized.

## Testing and examples

The registered Solidity test source exercises the interface and its canonical-form behavior. Tests support the implementation only; they do not supply missing normative authority.

## Open questions

- Current evidence gap: `normative_spec` is unregistered.
- Profile semantics and higher-layer verification remain deliberately outside the anchoring interface.
