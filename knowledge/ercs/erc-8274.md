# ERC-8274: AI Inference Proof Verification Interfaces

## Summary

The agent-ercs implementation draft separates cryptographic proof verification, agent-aware authorization and routing, and a settlement contract's declaration of its trusted verifier.

## Status

The org implementation was verified, but no canonical normative source is registered. Treat the number and interface shape as a working implementation proposal.

## Motivation

Inference systems need a stable composition boundary between proof-system-specific checks and application decisions about which agents and verifiers are trusted.

## Architecture

A verifiable application points to an agent verifier, which applies identity and routing policy before delegating cryptographic checks to a stateless proof verifier.

## Interfaces

The implementation describes three roles: a proof verifier, a stateful agent verifier, and a declaration interface for contracts that consume verification.

## State machine

The registered evidence describes verification calls and composition rather than a normative lifecycle. Concrete implementations define request, authorization, verification, and consumption states.

## Implementation

The org source is proof-system agnostic and is intended to accommodate mechanisms such as zero-knowledge proofs, optimistic verification, or trusted execution evidence.

## Security considerations

Callers must bind the proof to the intended agent, inputs, outputs, domain, and settlement action; a valid cryptographic proof alone does not establish application authorization.

No registered test or example source was available in this operation.
