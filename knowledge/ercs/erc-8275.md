# ERC-8275: Agent Reputation Layer

## Summary

The scoped agent-ercs implementation draft derives reputation from publicly recomputable settlement and attestation history instead of storing an opaque score.

## Status

Only implementation evidence is registered. No canonical normative source was available, so this page is an orientation to the org implementation, not a standards-compliance claim.

## Motivation

Trust signals are more useful when a consumer can reproduce their inputs and retain losses, counterparty diversity, and outcome history instead of trusting a scorer's assertion.

## Architecture

An off-chain reader derives reputation from public events and optional verified attestation history. The interface exposes derived values while the underlying record remains independently inspectable.

## Interfaces

The current org scope centers on an agent reputation interface; broader discovery, escrow, and mesh-settlement surfaces described by the proposal are not all implemented in this folder.

## State machine

Reputation changes as settlement and attestation events accumulate. It is a derived view, not a mutable on-chain reputation state machine in the registered source.

## Implementation

The source emphasizes outcome rate, settled volume caps, distinct counterparties, and independence-aware attester weighting so raw event count cannot dominate the result.

## Security considerations

Consumers must retain negative outcomes and defend against Sybil counterparties and apparently distinct attestations controlled by the same operator.

## Testing and examples

No registered test or example source was available in this operation.
