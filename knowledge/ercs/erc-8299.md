# ERC-8299: Input Provenance for AI Inference

## Summary

The agent-ercs implementation draft links the raw material a user submitted to the transformed input a model actually consumed, then extends the same chain-of-custody idea to judged and executed actions.

## Status

Only the Trustless AI implementation source is registered. No canonical normative source is available, so this is not a verified compliance description.

## Motivation

Reproducible AI execution needs to distinguish user input, sanitization or preprocessing, model input, proposed action, reviewer verdict, and the action ultimately executed.

## Architecture

The current source describes an input-provenance attestation layer and a higher judgment/execution attestation layer, sharing common claim typing and signing-domain conventions.

## Interfaces

One interface binds raw-input, pipeline, and model-input hashes. Another binds a proposal hash, verdict hash, and executed-action hash.

## State machine

Evidence moves from a pre-execution commitment through processing and judgment to a post-execution outcome. Exact lifecycle enforcement depends on the consuming gateway and settlement system.

## Implementation

The org source uses hash commitments and typed attestations so each stage can be checked without persisting the underlying private or bulky artifact on-chain.

## Security considerations

Canonical serialization, domain separation, signer authorization, timestamp ordering, record availability, and explicit no-op semantics are necessary to avoid convincing but unrelated hash chains.
