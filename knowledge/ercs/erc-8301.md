# ERC-8301: AI Agent Execution

## Summary

The agent-ercs implementation draft models agent execution as a contract-driven workflow whose tasks, replies, gates, and terminal result form a traversable evidence chain.

## Status

The org implementation source was verified. No canonical normative source or registered tests were available, so the behavior remains an implementation proposal.

## Motivation

Multi-step agent work needs deterministic ordering and an audit path showing which replies caused each task and which gates admitted every transition.

## Architecture

A workflow contract emits an initial task, receives agent replies, applies gate logic, and emits subsequent tasks or a terminal completion record.

## Interfaces

The implementation centers on a workflow interface plus task, reply, and run-status data structures.

## State machine

`run` creates the initial task. Each accepted reply advances to another task or the terminal state; rejected or expired paths are defined by the concrete workflow implementation.

## Implementation

Bidirectional hashes connect tasks to the replies that caused them and replies to the tasks they answer, allowing traversal from the final result back to the initial run.

## Security considerations

Gate authorization, expiry, replay prevention, hash-domain separation, and terminal-state integrity must be enforced by the contract rather than trusted to an off-chain agent.

## Testing and examples

No registered test or example source was available in this operation.

## Open questions

- Current evidence gaps: `normative_spec` and `test_or_example` are unregistered.
- Concrete workflows must define failure, cancellation, and timeout semantics.
