# ERC-8323: Source-Token Agent Binding for ERC-8004

## Summary

The agent-ercs implementation draft binds an ERC-8004 agent to a pre-existing ERC-721 source token while separating immutable provenance from current ownership.

## Status

Implementation and community discussion were verified. No canonical normative source or registered tests were available, so this remains a working proposal.

## Motivation

An agent may derive identity from a PFP, membership token, game character, or other NFT without forcing custody or making historical reputation follow a later buyer.

## Architecture

Registration records a permanent source collection and token relationship. A separate view rechecks present ownership whenever a consumer needs a live validity decision.

## Interfaces

The source separates a full registration-and-read interface from a read-only source-binding interface, with independently derived ERC-165 identifiers.

## State machine

Source provenance is written once at registration. Ownership validity changes as the source token or agent ownership changes and is recomputed rather than cached.

## Implementation

The org implementation recognizes direct ownership, a pinned canonical token-bound account, or the binding contract itself as valid custody patterns without transferring the source token.

## Security considerations

Consumers must not equate historical provenance with current ownership. Broadly accepting any token-bound account or advertising an unsupported full interface can create false validity claims.

## Testing and examples

No registered test or example source was available in this operation.

## Open questions

- Current evidence gaps: `normative_spec` and `test_or_example` are unregistered.
- Cross-registry resale and remint policy needs explicit ecosystem convention.
- Community discussion is informative, not normative.
